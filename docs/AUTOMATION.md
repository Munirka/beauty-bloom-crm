# Подключение n8n

[Workflow JSON](../public/automation/beauty-bloom-n8n.json) подготовлен для импорта. Внешний n8n/SMTP в демо не настроен; доставка не проверена.

| Событие | Задачи |
|---|---|
| Создание/перенос | Подтверждение сразу, напоминание за 24 часа |
| Завершение | Приглашение через 21 день (ногти) / 42 дня (волосы) |
| Отмена/неявка | Отмена старых задач |
| Нет email/согласия | Задача пропускается |

Переключатели CRM управляют выдачей. **Проверить в демо** переводит готовые задачи в demo_done, внешний сервис не вызывается.

## Настройка рабочей копии

1. Разверните отдельную студию для настоящих контактов. Портфолио заполнено вымышленными `@example.com`; отправлять seed-письма не нужно.
2. CRM → Автоматизации → Подключение n8n: скачайте workflow и создайте токен. Он показывается один раз; повторный выпуск отзывает предыдущий.
3. Импортируйте JSON в n8n. Workflow изначально неактивен.
4. Настройте BEAUTY_BLOOM_URL (без завершающего `/`) и BEAUTY_BLOOM_FROM (отправитель). Шаблон использует `$vars`; если Variables недоступны в вашей редакции, замените выражения конкретным URL/отправителем.
5. Создайте credential **Header Auth**: `Authorization: Bearer <токен>`. Назначьте его трём HTTP-узлам и удалите из них ручной Authorization header. `$vars.BEAUTY_BLOOM_TOKEN` в шаблоне обозначает место настройки; рабочий секрет храните в credential, а не экспортируемом workflow.
6. В **Send email** подключите собственный SMTP credential. Проверьте на контролируемом адресе в рабочей копии, затем активируйте workflow. Интервал — 5 минут, timezone — Asia/Almaty.

Шаблон требует проверки с вашей версией n8n и SMTP. Документация: [HTTP Request](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.httprequest/), [Send Email](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.sendemail/).

## Контракт API

POST `/api/integration/claim` с `Authorization: Bearer <токен>` возвращает `{"jobs":[{"id":"…","kind":"confirmation","email":"…","message":"…","lease":"…"}]}`. Пустой список — готовых задач нет. Резервируются до 20 задач на 10 минут.

POST `/api/integration/ack`: `{"id":"…","lease":"…","success":true}` или `{"id":"…","lease":"…","success":false,"error":"SMTP error"}`. Повторный ACK отклоняется 409. Ошибка: повтор через 5 минут, до 5 попыток. Origin не требуется — запросы авторизуются scoped-токеном.

SMTP допускает повторное письмо при сбое после отправки до ACK. Для более строгой гарантии замените SMTP на провайдер с idempotency key, используя job.id.
