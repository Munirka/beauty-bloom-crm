# Проверка писем через n8n

[Workflow JSON](../public/automation/beauty-bloom-n8n.json) подготовлен для импорта. Настройка внешнего SMTP и фактическое получение письма проверяются отдельно в собственном аккаунте. Демо по умолчанию не выдаёт задачи для отправки.

| Событие | Задачи |
|---|---|
| Создание/перенос | Подтверждение сразу, напоминание за 24 часа |
| Завершение | Приглашение через 21 день (ногти) / 42 дня (волосы) |
| Отмена/неявка | Отмена старых задач |
| Нет email/согласия | Задача пропускается |

Переключатели CRM управляют выдачей. **Проверить в демо** переводит готовые задачи в `demo_done`, внешний сервис не вызывается. В режиме тестовой отправки эта кнопка недоступна, чтобы случайно не забрать реальные тестовые задачи.

## Ограниченный тест настоящей почты

Администратор развёртывания задаёт два серверных значения (в production — секреты окружения Sites; локально — игнорируемый `.env.local` по образцу `.env.example`):

- `BEAUTY_BLOOM_TEST_OPERATOR_EMAIL`: email владельца, который входит через ChatGPT.
- `BEAUTY_BLOOM_TEST_RECIPIENT`: единственный адрес, принадлежащий тестировщику, для проверки доставки.

Настоящие адреса и ключи не добавляются в исходники, workflow, скриншоты портфолио или GitHub. Для локальных интеграционных проверок используется имитация входа и вымышленные `seedy@sites.test` / `delivery@controlled.test`.

В своей CRM войдите владельцем и включите **Тестовую отправку на настоящую почту** в Автоматизациях. Создайте новую запись на разрешённый email с согласием на уведомления. API выдаёт только задачи, созданные после первого включения теста, с этим адресом и актуальным состоянием визита. Демо-контакты `@example.com` исключены. Публичная форма принимает настоящий email только из серверного списка разрешённых; сам адрес публичный GET не раскрывает.

## Подключение n8n и SMTP

1. CRM → Автоматизации → Подключить n8n: скачайте шаблон и создайте токен. Он показывается один раз; повторный выпуск отзывает предыдущий.
2. Импортируйте JSON в n8n. Workflow неактивен, узел расписания выключен. Платные Variables не нужны.
3. В **Studio configuration** задайте `crmUrl` (адрес CRM без завершающего `/`) и `fromEmail` (подтверждённый отправитель).
4. Создайте credential **Header Auth**: имя `Authorization`, значение `Bearer <токен>` — с пробелом. Назначьте его узлам **Claim queued messages**, **Acknowledge success** и **Acknowledge failure**. Секрет хранится только в credential n8n.
5. В **Send email** подключите SMTP credential провайдера. Для Brevo: сервер `smtp-relay.brevo.com`; SMTP login берётся из кабинета, password — SMTP key, не API key; для порта 465 используйте SSL/TLS. Убедитесь, что транзакционная отправка активирована, отправитель подтверждён и домен настроен. Публичный домен iCloud не принадлежит тестировщику и не может быть аутентифицирован им в Brevo.
6. Включите тестовую очередь в CRM и создайте тестовую запись с согласием. Нажмите **Execute workflow**. Письмо помечается `[ТЕСТ Beauty Bloom]`.
7. Подтвердите получение в разрешённом почтовом ящике, включая папку спама. Статус **Принято почтовым сервисом** означает успешную передачу SMTP, а не доказанное попадание во входящие.
8. Для напоминания нажмите **Проверить сейчас** у задачи в журнале CRM и снова запустите workflow. Для приглашения сначала завершите визит, затем ускорьте появившуюся задачу повторного визита. Кнопка переносит срок в очередь и сама не отправляет письмо.
9. После проверки приостановите тестовую очередь, если дальнейшая отправка не нужна.

Для расписания включите узел **Every 20 minutes** и опубликуйте workflow, предварительно проверив тариф n8n. Это примерно 2160 запусков за 30 дней — больше 1000 запусков в бесплатном пробном периоде. Timezone — Asia/Almaty. Пробный период не является постоянным бесплатным хостингом; для постоянной работы нужен подходящий облачный тариф или самостоятельный хостинг n8n.

Документация: [Schedule Trigger](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.scheduletrigger/), [HTTP Request](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.httprequest/), [SMTP credential](https://docs.n8n.io/integrations/builtin/credentials/sendemail/), [Brevo SMTP](https://help.brevo.com/hc/en-us/articles/7924908994450-Send-transactional-emails-using-Brevo-SMTP), [лимиты n8n](https://n8n.io/pricing/).

## Контракт API

POST `/api/integration/claim` с `Authorization: Bearer <токен>` возвращает `{"mode":"test","jobs":[{"id":"…","kind":"confirmation","email":"…","message":"…","lease":"…"}]}`. При выключенном или ненастроенном тесте — `{"mode":"demo","jobs":[]}`. Пустой список в тесте означает отсутствие подходящих готовых задач. Резервируются до 20 задач на 10 минут.

POST `/api/integration/ack`: `{"id":"…","lease":"…","success":true}` или `{"id":"…","lease":"…","success":false,"error":"SMTP error"}`. Повторный, неправильный или просроченный ACK отклоняется 409. Ошибка: повтор через 5 минут, до 5 попыток. Origin не требуется — запросы авторизуются токеном очереди конкретной студии.

SMTP допускает повторное письмо при сбое после отправки до ACK. Для более строгой гарантии используйте провайдер с idempotency key на основе job.id. Тестовый режим предназначен для одного контролируемого ящика; многопользовательская рассылка и постоянная эксплуатация настоящего салона требуют отдельного развёртывания, надёжных прав сотрудников и соответствующей настройки доставки.
