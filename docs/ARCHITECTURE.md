# Архитектура

React → `/api/[...path]` → Zod + проверка сессии/роли → подготовленные SQL-запросы D1. Drizzle описывает схему, `drizzle/` содержит миграции. При запросах приложение не создаёт таблицы.

Таблицы: `workspaces`, `sessions`, `masters`, `services`, `clients`, `appointments`, `jobs`, `audit`. Каждая сущность принадлежит студии. Время визита: локальная дата и минуты от полуночи; сроки уведомлений: Unix milliseconds. Часовой пояс — Asia/Almaty.

Сессионный токен хранится в HttpOnly/SameSite cookie, его SHA-256 — в базе. На HTTPS cookie имеет Secure. Сессия длится 7 дней. Первый вход связывает анонимную студию с пользователем Sites; если аккаунт уже имеет студию, открывается она. После выхода cookie не даёт доступа к студии аккаунта. Переключатель роли предназначен для демонстрации, а не назначения сотрудников.

## API

POST браузера требует Origin текущего сайта и сессионную cookie. Ответы JSON, ошибки `{error: string}` с 400/401/403/404/409/429/503.

| Путь | Метод | Назначение |
|---|---|---|
| `/api/bootstrap` | GET | Данные студии с учётом роли |
| `/api/appointments` | POST | Создание с clientId или новым client |
| `/api/appointments/move` | POST | id, version, date, start, masterId |
| `/api/appointments/status` | POST | id, version, status: completed/cancelled/no_show |
| `/api/clients` и `/api/clients/update` | POST | Создание/редактирование клиента |
| `/api/masters`, `/api/services` | POST | Создание/редактирование справочников |
| `/api/session/role` | POST | Демонстрационная роль |
| `/api/settings` | POST | Переключатели сценариев |
| `/api/automation/demo` | POST | Обработка готовых задач без отправки |
| `/api/integration/key` | POST | Выпуск scoped-токена, отзыв предыдущего |
| `/api/reset` | POST | Восстановление текущей демо-студии |
| `/api/public?studio=<id>` | GET/POST | Свободные интервалы без контактов / онлайн-запись |

`start: 840` означает 14:00. Сервер повторно проверяет будущую дату (до 90 дней), рабочий день/часы, подходящее направление и отсутствие пересечений.

## Конкурентность

Создание: `INSERT … SELECT … WHERE NOT EXISTS`, проверка занятости и запись атомарны. Перенос: условный UPDATE с занятостью и `version`. Смена статуса тоже требует версию; устаревшая операция возвращает 409. Связанные задачи обновляются в D1 batch; отклонённая операция не отменяет актуальные задачи. Перенос сохраняет снимок цены/длительности.

## Очередь

`pending` → `processing` → `sent` / `failed`. Дополнительные состояния: skipped (нет согласия/email), cancelled, demo_done. Выдача зависит от включённого сценария и статуса визита. Lease — 10 минут; до 20 задач в одном claim, максимум 5 попыток, ошибка откладывает задачу на 5 минут. Токен интеграции ограничен одной студией и хранится в виде хеша.

ACK требует совпадение id, lease, студии и processing. SMTP допускает повтор после сбоя между отправкой и ACK; для однократной доставки нужен провайдер с idempotency key.

## WebMCP

При поддержке document.modelContext интерфейс регистрирует чтение расписания и открытие формы записи. Открытие только подготавливает видимую форму; запись создаётся её кнопкой. Без WebMCP обычный интерфейс работает полностью.
